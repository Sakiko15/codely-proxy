## 1. 流程梳理

### 1.1 启动链（`cmd/codely-proxy/main.go`）

```
config.Load()                      # env 配置
  → flag 覆盖                      # flag > env > 默认
  → SetDataDir × 4                 # account/oauth/balancer/security 各自包级 DataDir
                                   # ⚠️ 顺序敏感：必须先于各 New* 构造
  → atomicfile.CleanupTemp × 2     # 数据目录 + accounts/ 子目录，清扫崩溃残留 *.tmp
                                   # （残留可能是明文凭据，清扫是刻意的）
  → 接线 oauth 钩子                # OnGlobalRefreshed=SyncCurrentFromActivation
                                   # OnRotationRejected=SyncCredsByIdentity
                                   # 全局刷新/轮换拒绝回同步 per-slug 文件，勿断开
  → 构造注入                       # Registry→Balancer→Security→Quota→LoginFlow→Proxy→Handler→WebUI
  → 后台 Preheat()                 # 4 worker 预热 key 与额度快照
  → http.Server                    # WriteTimeout:0 刻意（SSE 长流必需）
                                   # ReadHeaderTimeout 10s / ReadTimeout 120s / IdleTimeout 90s
  → SIGTERM/SIGINT 15s 优雅退出，二次信号强制退出
```

### 1.2 代理请求调用链（热路径）

```
webui/server.go:91  mux /v1/ → proxy.Handler
  → ServeHTTP                      # 32MB body 限流
  → handle：
     reqlog defer push             # 环形缓冲，一次请求一条（probe 跳过）
     ① Security.Validate           # Bearer / X-Api-Key，constant-time；未配置 key = 放行（trust mode）
     ② HasImageBlocks → 400 早拒   # /messages 图片块上游整体损坏，指引走 OpenAI 端点（§19.3-①）
     ③ ExtractStops                # 停词提取（上游两端口皆坏，代理自执行，§19.3-②）
     ④ 重试循环 ≤ min(3, 账号数) × 2：
        Balancer.Pick              # X-Codely-Account 可钉住；quota-first 并行查额度 / round-robin
                                   # 冷却中/禁用账号排除
        AccountState.GetAPIKey     # 内存 → accounts/<slug>.key → singleflight 刷新（过期前 60s）
        Proxy.AttemptForward       # sanitize.TransformBody（session 注入/system 清洗/剥 thinking）
                                   #   → /messages 精确路径追加 ?beta=1
                                   #   → gateway.SignRequest HMAC（每请求新签）
                                   #   → CLIENT_HEADERS（CLI 身份伪造，字节冻结契约）
                                   #   → Client.Do（无全局 Timeout；ResponseHeaderTimeout=120s 兜底首字节）
        结果分类                   # KindOK / KindRetryKey(401/403) / KindModelDenied /
                                   # KindQuotaRateLimit(402/429 → MarkFailure 冷却) / KindError
     ⑤ pipeResponse                # 非 SSE io.Copy；SSE → flushWriter 逐事件 Flush → sseguard
                                   #   （Anthropic 流中断合成收尾三件套 / OpenAI 补 [DONE]，golden 契约）
                                   # 停词：非流式 TrimStopBody / 流式 holdback-trim 模式
                                   # GET /v1/models → OverrideModelsMeta（alias→窗口静态表覆写，§19.3-③）
     → 环形缓冲入环                # 终态一条（x-codely-routed-account 头带路由账号）
```

**headersWritten 两阶段模型**（`rwTracker`）：响应头一旦发出，绝不 failover、绝不重写状态码、绝不 markAccountFailure，只能由 sseguard 收尾——违反正是 Node 版挂死客户端、误标健康账号的根源。

### 1.3 账号状态生命周期

```
设备码登录（唯一加账号路径，internal/account/login_flow.go）：
  Start   → 申请设备码（内存槽，防并发）
  Poll    → 轮询授权（slow_down +5s，间隔上限 30s）
  complete→ token 兑换 → me/teams 取身份
          → slug 碰撞检查（-N 后缀）
          → SaveAccount 五步序：① <slug>.json → ② invalidate 旧凭据 → ③ codely-creds.json
                                → ④ index.json（失败回滚 restoreActivationLocked）
                                → ⑤ 删遗留 key.cache/session.cache
          → ReloadPool → <slug>.session 会话 UUID 写入

运行时：GetAPIKey / persistCreds 双写带同步身份守卫（全局刷新/轮换拒绝回写 per-slug 文件）
激活：  ActivateAccount（r.mu 内 读→clearCaches→写激活→提交 index.Current，失败回滚）
删除：  RemoveAccount（index 提交 → 删文件 → 级联激活下一账号 → ReloadPool → OnAccountRemoved）

重启：CleanupTemp → codely-creds.json 遗留导入 → syncPool → Preheat
```

状态持久化（无数据库，全部数据目录文件，写入一律走 `internal/atomicfile` 包级互斥串行化）：

```

codely-creds.json          # 恒等于当前激活账号（旧版兼容入口，启动导入）
balancer.json / proxy-key.txt
遗留 key.cache / session.cache   # 只删不写
```

## 2. 审计发现

> 状态列：待修 → 修复中（提交号）→ 已修复。修复提交回填本表形成解码环。

### 2.1 P1

#### P1-A 总览页额度强制刷新 100% 失效（405 回归）

- **位置**：`internal/webui/web/pages/overview.js:57`；路由 `internal/webui/server.go:68`
- **现象**：强制刷新按钮调 `apiPost('/api/quota?force=1')`，但路由只注册 `GET /api/quota` → 405，按钮完全失效。
- **根因**：WebUI 重构（adb7618）时把旧版的 GET 误改成了 POST。
- **修复**：改回 `apiGet`；针刺测试补意图断言。**状态：已修复（208bb8c）**

#### P1-B 客户端断开被当作上游故障，误标健康账号

- **位置**：`internal/proxy/forward.go:124,160-162`；`internal/proxy/handler.go:307-316`
- **现象**：上游请求用 `r.Context()` 发起（`http.NewRequestWithContext`，§19.1 中止计费的刻意设计），客户端 ESC 取消 → `Client.Do` 返回 `context.Canceled`，在 `forward.go:160-162` 与真实网络错误一同归为 `KindError`；`handler.go:307-316` 该分支无任何 ctx 检查，直接 `MarkFailure(slug, 502)` + 排除 + failover。
- **触发**：用户中断一次长流 → 1~3 个健康账号被误标失败进入 5min 冷却，reqlog 记假 502；单账号部署直接自锁（余额照扣、无流可看）。
- **修复**：KindError 分支 MarkFailure 之前查 `r.Context().Err()`，已取消则中止循环返回（不 MarkFailure、不 failover、reqlog 记 client-abort 而非 502）；`forward.go` 的 `errors.Is(err, context.Canceled)` 单列语义由 handler 侧 ctx 门完全覆盖，无需重复。**状态：已修复（批次 2）**

### 2.2 P2

#### P2-C 设备码弹窗监听器重复绑定

- **位置**：`internal/webui/web/pages/accounts.js:20-79`（`wireDevLogin`）
- **现象**：`#dev-login-modal` 是常驻 shell（index.html outlet 外）的弹窗，但 `wireDevLogin` 在账号页每次 mount 都重绑 copy/open/close 监听器 → N 次访问后点一次复制弹 N 个 toast / 开 N 个标签页。注释所称"只绑一次"实际不成立。
- **修复**：绑定状态持久化（模块级标记或移至 main.js 一次性绑定）。**状态：已修复（批次 3）**

#### P2-C2（连带）api.js 在途去重键缺 body

- **位置**：`internal/webui/web/assets/api.js:22`
- **现象**：去重 key 只有 `method + ' ' + path`，并发 POST `/api/account/delete` 删**不同**账号时第二个请求被静默吞掉（返回第一个的 Promise）。
- **修复**：去重仅对幂等的 GET 生效，非 GET 直接不去重（同时消灭探针误并）。**状态：已修复（批次 3）**

#### P2-D matchMedia 监听器无界泄漏

- **位置**：`internal/webui/web/assets/main.js:88-104`
- **现象**：每次 `matchMedia('(prefers-color-scheme: light)')` 返回**新的** MediaQueryList 实例，对其 `removeEventListener` 永远移不掉旧监听器 → 每次手动切换主题累积一个监听器。
- **修复**：模块级持有单实例复用，监听器只在 init 挂一次。**状态：已修复（批次 3）**

#### P2-E 日志页过滤态换页丢失同步

- **位置**：`internal/webui/web/pages/logs.js:31-52`
- **现象**：mount 重置 fullReload/lastSeq/view 但漏了模块级 `kindFilter`，下拉框显示"全部"实际仍按旧过滤。
- **修复**：mount 重置 `kindFilter` 并同步 select 的 `selected`。**状态：已修复（随 P1-B 提交 2d3cc00 入库）**

#### P2-F sseguard trim 模式只处理 choices[0]，流式 n>1 停词泄漏

- **位置**：`internal/sseguard/guard.go:583-635`（`trimChunk`/`rewriteChunk`）
- **现象**：probe/改写仅取 `Choices[0]`，choices[1+] 的 delta.content 不进待定区直接透传 → 停词泄漏。与非流式 `stoptrim.go:153-191`（全 choices 处理）不对称。
- **影响**：仅停词模式 + 流式 n>1 时触发（罕见）。
- **决定**：**核实后暂不修**——上游网关流式实测单 choice（resp.model 映射单后端），修复需改 rewriteChunk 的多 choice 改写路径、贴近 golden 契约敏感区，风险收益不成比；落档为已知边界，待上游支持 n>1 时一并处理。

#### P2-G 删除账号可被"复活"

- **位置**：`internal/account/registry.go`（RemoveAccount / ReloadPool / `SaveAccount` 无条件 upsert）；`internal/balancer/account_state.go`（persistCreds）
- **现象**：① `RemoveAccount` 删文件失败（如 Windows AV 锁）→ `ReloadPool` 文件优先重建已删账号，后续 `persistCreds→SaveAccount` 把 index 条目写回；② `SaveAccount(activate=false)` 无条件 upsert，在途轮换/持久化可把并发删除中的账号写回 index。
- **修复**：双入口封堵，ReloadPool 语义不动——① RemoveAccount 凭据文件删除失败 → **回滚 index 提交并报错**（removed=false，注册表与磁盘一致，重试即可；修订 2026-08-28 P2 #15 的"removed 恒 true + warning"契约）；② 新增 `SyncRotatedCreds`：只回写注册表现存账号，查无此 slug 即拒绝（persistCreds 与激活预取两处调用点改用），`SaveAccount` 契约不变。**状态：已修复（批次 4）**

#### P2-H 注册表热路径每请求读盘

- **位置**：`internal/account/registry.go`（GetCurrentName/GetCurrentMeta → loadIndex）
- **现象**：持 `r.mu` 期间 `os.ReadFile + Unmarshal` index.json，每次代理请求至少一次。
- **修复**：loadIndex 改 mtime 校验的内存快照缓存（返回值**只读共享**，写者先 cloneIndex；saveIndex 写后显式刷新缓存，规避 mtime 粒度同 tick 撞车），热路径零读盘。**状态：已修复（批次 4）**

#### P2-I syncPool 锁内写盘

- **位置**：`internal/balancer` syncPool → `NewAccountState→initSession`（写 `.session` 文件）
- **现象**：持 `b.mu+r.mu` 期间做磁盘 IO。
- **修复**：initSession 只读/生成（新生成记 `sessionDirty`），新增 `ensureSessionPersisted` 由 syncPool 在释放 b.mu 后对新建账号补写——单次构造与 Pick 阻塞语义不变，落盘移出临界区。**状态：已修复（批次 4）**

#### P2-J 登录 slug 碰撞检查与保存竞态

- **位置**：`internal/account/login_flow.go` complete；`internal/account/registry.go`
- **现象**：碰撞检查（-N 后缀决策，f.mu）与 `SaveAccount`（自取 r.mu）跨锁释放构成 check-then-act，并发登录同名可双写。
- **修复**：抽取 `saveAccountLocked`，新增 `SaveAccountAutoSlug` 把碰撞检查与保存合并进同一 r.mu 临界区，complete 改调之。**状态：已修复（批次 4）**

#### P2-K body 重复解码

- **位置**：`internal/proxy/handler.go:190,209`；`internal/proxy/forward.go:101`
- **现象**：同一 body 每请求至多 6 次全量 JSON 解码：HasImageBlocks + ExtractStops 各一次，TransformBody 在 attemptLoop 内每次尝试重复执行。
- **决定**：**核实后暂不修**——TransformBody 无副作用幂等，典型 body 小（KB 级），32MB 是上限非常态；重构需改 `AttemptForward` 签名、波及 JS 对齐注释（GO_PORT §0），收益仅限大 body 多次重试的非常态路径。落档待观测。

### 4.2 核实后不做（防误报）

| 项 | 理由 |
|---|---|
| P2-K body 重复解码缓存化 | 须改 `AttemptForward` 签名（GO_PORT §0 对齐注释波及）；维持 §2.2 落档 |
| admin 端点 TimeoutHandler | 有效超时须 ≥300s 才不误伤 quota force，届时兜挂起价值趋零；且超时后 handler 继续跑完会造成"前端 503 但账号已入库"误报 |
| /healthz 读盘缓存化 | 30s 一次 × KB 级，缓存反引入凭据轮换失效复杂度 |
| security.Validate 的 stat 加 TTL | 改变 proxy-key 热加载生效时延（行为变化） |
| atomicfile 包级单锁细化 | 该锁是同目标并发写（全局刷新 vs ActivateAccount）唯一防拼接损坏屏障 |
| body 缓冲池化 | 收益仅大 body 高并发，池化别名滞留风险不值 |
| 登录 Cancel 无 slot 身份竞态 / GetStatus 轮询读盘 / limiter 闲时清扫 | 收益极小或跨 API 形态 |
