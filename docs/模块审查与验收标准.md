# codely-proxy 功能模块审查蓝图与验收标准

> 用途：本仓库全部功能模块审查的**统一执行基准**。任何审查会话（人或 Claude）按本文档逐模块执行，
> 结论填入 §4 记录表。审查发现的修复完成后，以本文档标准复验。
>
> 取材权威：`CLAUDE.md`（架构与关键约束）、`docs/GO_PORT.md`（移植契约与质量目标）、
> `docs/PROTOCOL.md` / `docs/PROTOCOL_SCHEMA.md`（上游协议契约）、仓库测试文件（验收标准绑定）。
>
> 维护规则：架构变化（新增数据文件、新端点、新包）时同步更新对应模块卡与验收标准。

## §0 使用说明

### 0.1 审查流程

```
§1 全局门槛（先跑，任一不过则先修复再进模块审查）
  → §2 模块卡 M1-M13 逐个执行：
      ① 读「职责与关键文件」确定范围
      ② 对照「契约权威」章节通读代码
      ③ 「不变量清单」逐条核对（每条给出 ✅/❌ + file:line 证据）
      ④ 「审查要点」六维扫描（正确性 / 并发 / 错误路径 / 资源 / 安全 / 性能）
      ⑤ 「现有测试覆盖」跑绑定命令确认绿
      ⑥ 「验收标准」逐条判定，填 §4 记录表
  → §3 横切项核对
  → 汇总结论
```

### 0.2 结论分级

| 标记 | 含义 | 要求 |
|---|---|---|
| ✅ 通过 | 全部验收标准满足 | 无 |
| ⚠️ 有保留通过 | 主体满足，存在不影响正确性的保留项 | 必须在记录表列出每条保留项及理由 |
| ❌ 不通过 | 任一验收标准不满足 | 列出缺陷（分级 + file:line 证据 + 复现方式） |

### 0.3 缺陷分级

- **P0**：崩溃 / 数据损坏或静默丢失 / 上游协议契约违约 / 安全漏洞（凭据泄露、路径穿越、注入）
- **P1**：功能错误、边界条件错误、状态机死角、错误的用户可见行为
- **P2**：健壮性缺口（无超时、错误被吞）、可维护性、性能

### 0.4 证据要求

每条结论必须可追溯：代码结论附 `file:line`；测试结论附测试名与运行结果；人工核对项附对照来源（如 GO_PORT §14 对照表逐项勾选结果）。**不接受"看起来没问题"式的无证据结论。**

### 0.5 复审规则

任何代码改动后：重跑受影响模块卡的全部验收命令 + §1 全局门槛（G1-G8）。改动触及 §2 卡中标 ⭐ 的**金契约**（SSE 字节级 golden、签名算法、错误格式映射）时，必须逐字节确认契约未漂移。

## §2 模块审查卡

> 每张卡六段固定结构。⭐ 标记 = 金契约（违反即 P0）。「现有测试覆盖」中的测试名可直接用
> `go test ./<pkg>/ -run '<TestA|TestB>' -count=1` 批量执行。

### M1 装配与生命周期（cmd/codely-proxy/main.go，181 行）

**职责**：进程入口——config.Load → flag 覆盖 → 四包 SetDataDir（顺序敏感）→ 装配 Registry/Balancer/Security/Quota/Proxy/Handler/WebUI → http.Server → 信号处理。

**契约权威**：GO_PORT §12/§15；CLAUDE.md 架构节。

**不变量**（逐条核对）：
- A1：配置优先级 flag > env > 默认（flag 默认值取自 env，显式传参覆盖）
- A2：`SetDataDir` 四包（account/oauth/balancer/security）调用必须先于任何 New\* 构造（顺序敏感）
- A3：`http.Server.WriteTimeout = 0` 是刻意的（SSE 长流必需），不得"修复"
- A4：SIGTERM/SIGINT → 15s 优雅停机（等待在飞请求），二次信号强退
- A5：`WEBUI_PASS` 未设 → 随机密码生成并打印日志（启动横幅含用户名/密码/固化提示）

**审查要点**：正确性（装配依赖完整性）；错误路径（端口占用/数据目录不可写的启动失败表现）；资源（goroutine/计时器是否随停机清理）；安全（随机密码仅打印不落盘）。

**现有测试覆盖**：❌ 无——入口包零测试（装配顺序、优雅停机路径均无测试，属已知缺口）。

**验收标准**：
- M1-A1：走查 `main()` 装配顺序与 A1-A3 三条不变量（代码核对，附 file:line）
- M1-A2：冒烟——不设 env 启动，日志出现随机密码横幅；`--port` 覆盖 `CODELY_PROXY_PORT` 生效
- M1-A3：`kill -TERM` 后进程在 15s 内退出且日志含优雅停机记录
- M1-A4：`CODELY_DATA_DIR` 指向不可写路径 → 启动失败有明确错误而非静默

- M2-A2：走查 `defaultDataDir`——`runtime.GOOS != "windows"` 守卫 + `st.IsDir()` 检查在位（file:line）

### M3 上游协议层（internal/gateway，78 行）⭐ 含签名金契约

**职责**：纯协议层——X-Codely-Signature HMAC 签名。（上游逆向知识，一字不改）
> 位置注记（审查记录 2026-08-28）：CLI 头组实际定义于 `internal/oauth/apikey.go:128`、session UUID 于 balancer/oauth——GO_PORT §1 规划目录与实际的已知漂移。

**契约权威**：GO_PORT §2；PROTOCOL §2.4/§2.3；PROTOCOL_SCHEMA §15/§16。

**不变量**：
- A1：⭐ `CodelySignature` 输出与 JS 版逐字节一致（`v1.<10位秒>.<43位base64url>`）；SECRET/派生链不得改动
- A2：`SignRequest` 每请求新签（新时间戳，绑定 key + 去 query 的 path），**不缓存**
- A3：签名 pathname 为**去 query 的纯路径**（`?beta=1` 追加不影响签名）
- A4：CLI 头组（UA + X-Stainless-\*）单处定义，不得漂移出第二份

**审查要点**：正确性（算法与格式）；性能（无锁无分配热点）。

**现有测试覆盖**：`TestCodelySignatureGolden`（JS 对拍 golden）、`TestCodelySignatureFormat`、`TestSignRequest`、`TestSignRequestPathnameBinding`（4 个）。

**验收标准**：
- M3-A1：`go test ./internal/gateway/ -count=1` 全绿（golden 逐字节过）
- M3-A2：走查 `SignRequest`——确认无缓存、`u.Path`（非 RawQuery）参与签名
- M3-A3：对照 PROTOCOL_SCHEMA §16 确认头组值一字不差

### M4 OAuth 凭据与控制面（internal/oauth，771 行）

**职责**：codely-creds.json 读写与刷新、sk- 密钥换取（401→refresh 轮换重试）、模型列表/后端探测、通用 HTTP 辅助。

**契约权威**：GO_PORT §7；PROTOCOL §1；PROTOCOL_SCHEMA §1/§2/§3/§9/§12/§15/§16。

**不变量**：
- A1：**按账号 vs 全局刷新双轨** ⭐——池内账号必须 `RefreshAccessTokenFor(creds)` 并由调用方回写 `accounts/<slug>.json`；全局 `RefreshAccessToken()` 写 codely-creds.json（当前激活账号），池路径勿用
- A2：refresh/fetch key 均 singleflight 防重；轮换式刷新必须把**新 refresh_token** 交还调用方持久化（丢失即账号报废）
- A3：FetchAPIKey 非 `sk-` 前缀必须报错；401 → 刷新重试恰一次
- A4：控制面 HTTP 统一 `HTTPClient`（30s 超时 + 共用 Transport）；转发/SSE 勿用此客户端（会掐死长流）
- A5：`FlexString` 容忍 string/number/null 混发，**勿收紧类型** ⭐
- A6：控制面请求带 CLI UA；非 2xx 错误含状态码 + `BodySnippet`（响应体前 256 字节摘要）

**审查要点**：并发（singleflight 语义：全员共享同一结果与错误）；错误路径（无 refresh_token 直接报错不发请求）；安全（凭据日志脱敏）。

**现有测试覆盖**：`TestFetchAPIKey`、`TestFetchAPIKeySkPrefixRequired`、`TestFetchAPIKeyRefreshOn401`、`TestFetchAPIKeyReturnsRotatedCreds`、`TestRefreshAccessToken`、`TestRefreshAccessTokenNoRefreshToken`、`TestFetchAvailableModels`、`TestProbeBackends`、`TestProbeBackendsMajority`（9 个）。缺口：`PostJSON`/`Get`/`BodySnippet`、`GetAccessToken`/`IsExpiring` 无直接测试。

**验收标准**：
- M4-A1：`go test ./internal/oauth/ -count=1` 全绿（9 测试全过）
- M4-A2：走查 `FetchAPIKeyReturnsRotatedCreds` 语义——轮换路径返回新 creds 实例、直通路径返回入参同指针
- M4-A3：`go test -race -count=1 ./internal/oauth/` 干净

### M5 多账号注册表与设备码登录（internal/account，997 行）

**职责**：accounts/index.json + `<slug>.json` 注册表、Slugify/AutoName、激活切换、级联删除、legacy 导入；设备码登录状态机（initiate→poll→exchange→me/teams→登记激活）。

**契约权威**：GO_PORT §6；PROTOCOL §1/§8；PROTOCOL_SCHEMA §2/§4/§14。

**不变量**：
- A1：slug 白名单 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`，写文件前必须 slugify（防路径穿越）⭐；`index` 为预留字（与 index.json 同名互覆）
- A2：激活语义 = 复制凭据到 codely-creds.json + 删 key.cache/session.cache——**codely-creds.json 恒等于当前激活账号** ⭐
- A3：撞名加 `-2` 后缀且碰撞检查在 slug 域；userId 空串不得命中"同 user 重建"分支（防静默覆盖）⭐
- A4：删除账号必须清理 `<slug>.key/.session` 伴生文件；删当前账号级联切换，级联失败不得谎报 removed=true 且必须清除指向已删账号的 codely-creds.json
- A5：`ListSlugs` 缓存用独立 `slugsMu`（`SaveAccount` 持 r.mu 经 ReloadPool→syncPool→ListSlugs 再入会用 r.mu 自死锁）⭐；目录 mtime + 显式失效（Windows NTFS 目录 mtime 惰性更新）
- A6：sk- 密钥预取（网络）不得持 r.mu（`TestActivateAccountPrefetchOutsideLock` 钉死）
- A7：登录状态机——poll 按上游 `interval` 节流；`slow_down` → interval+5（封顶 30）；authorized 终态 CAS 取走 slot（防双 complete / 迟到终态误杀新登录）；poll 异常折叠 pending 但 message 含状态码与错误体摘要并在节流窗口内持续回传
- A8：登录态仅存进程内存（重启作废）；Start 失败保留旧 slot（进行中的登录不被打断）
- A9：index.json 损坏 → 返回空注册表不 panic

**审查要点**：并发（r.mu/slugsMu 锁序、CAS 语义）；错误路径（exchange 失败文案、me/teams 非致命记日志、激活失败如实报错）；安全（slug 穿越面）；性能（mtime 缓存）。

**现有测试覆盖**（21 个）：`TestSlugify`、`TestAutoName`、`TestSaveListActivate`、`TestRemoveAccountCascade`、`TestEnsureRegistryImportsLegacy`、`TestCredFingerprint`、`TestDeviceLoginFlow`、`TestDeviceLoginSameAccount`、`TestPollNoLogin`、`TestDeviceLoginPollThrottleAndMessage`、`TestDeviceLoginSlowDownBackoff`、`TestDeviceLoginStalePollNoComplete`、`TestDeviceLoginCollisionEmptyUserID`、`TestAutoNameUpperUserID`、`TestRemoveAccountRemovesSidecarFiles`、`TestRemoveAccountCascadeSwitchFail`、`TestSlugifyReserveIndex`、`TestListSlugsCache`、`TestDeviceLoginSameNameCollision`、`TestActivateAccountPrefetchOutsideLock`、`TestLoadIndexCorruptedFile`。

### M6 负载均衡（internal/balancer，931 行）

**职责**：账号池 + 调度（Pick：quota-first 分层 / round-robin / preferred / excluded）、冷却与指标、配置持久化、Preheat、状态聚合视图。

**契约权威**：GO_PORT §8；PROTOCOL_SCHEMA §5/§11。

**不变量**：
- A1：quota-first 分层语义——先日额度（dailyRemaining>0）后账单点数，同层 round-robin；两子集独立游标
- A2：⭐ 冷却规则——`KindQuotaRateLimit`（402/429）**恒先冷却**当前账号，哪怕错误最终透传、无 failover（否则末账号持续吸收 402）；502 等非额度类不冷却只计 metrics
- A3：`X-Codely-Account` preferred 直返（冷却/禁用校验后）；enabled=false 恒回退当前激活账号
- A4：`MarkFailure` 关键词判定限前 2KB、冷却原因截断 ~256 字节
- A5：锁序 `r.mu → b.mu → slugsMu` 无反向边 ⭐；`GetStatus` 不得在持 b.mu 时调 GetCurrentName
- A6：UpdateConfig 深拷贝快照 + saveMu；persist 失败上报错误但内存已生效
- A7：OnAccountRemoved 清理 disabledSlugs 残留（幂等）
- A8：Preheat 有界预热（LB 开启且 quota-first 才预热 quota）；key 文件齐备时零网络

**审查要点**：并发（轮询游标原子性、并发 FetchQuota）；正确性（分层回退路径）；资源（quota 缓存 30s SWR）。

### M7 请求清洗（internal/sanitize，296 行）

**职责**：transformBody 编排——session 注入、违禁词清洗（system-only）、assistant 历史 thinking 剔除、顶层 RawMessage 重组与零拷贝。

**契约权威**：GO_PORT §3/§17.2/§19.2；PROTOCOL_SCHEMA §6。

**不变量**：
- A1：⭐ 违禁词改写**只碰 `system` 字段**（string 或 content 数组）；messages 里用户代码同名文本不得被改（§17.2 决策）
- A2：⭐ body 重组用顶层 `json.RawMessage`（值字节保留、大整数不失真、无改动场景零拷贝直通），**勿改回 `map[string]any` 全量往返**
- A3：历史 thinking/`redacted_thinking` 块剔除默认开；`KEEP_THINKING_HISTORY=1/true` 保留；`thinking: {type: enabled...}` 本轮参数原样透传（剔除 ≠ 不透传）
- A4：防御——顶层 null / messages 含非对象 / metadata 脏类型 / `"system":null` 均保守跳过不 panic
- A5：清洗幂等（第二次跑 changed=false 字节一致）
- A6：session 注入语义——缺失/空/非字符串才补顶层 + metadata.session_id；客户端自带不动

**审查要点**：正确性（未知字段零透传丢失）；性能（零拷贝判定路径）；安全（正则改写面）。

## §5 验收命令速查

```bash
# —— 组 1：全局门槛（每次审查必跑）——
go build ./...
go vet ./...
go test -count=1 ./...

# —— 组 2：竞态（核心并发包）——
go test -race -count=1 ./internal/account/ ./internal/balancer/ ./internal/proxy/ ./internal/webui/ ./internal/oauth/

# —— 组 3：金契约 ——
go test ./internal/sseguard/ -run Golden -count=1        # SSE 字节级 golden（TestAnthropicSynthesizedBytesGolden）
go test ./internal/proxy/ -run 'Tripwire|Failover|NoGlobalTimeout' -count=1  # 转发回归 tripwire（3 个回归测试）
go test ./internal/gateway/ -count=1                     # 签名算法 golden
go list -m all                                           # 零依赖（应仅 golang.org/x/sync）

# —— 组 4：单模块定点（示例，按模块卡「现有测试覆盖」段替换 -run 列表）——
go test ./internal/balancer/ -run 'TestPick|TestMarkFailure|TestCooldown' -count=1
```
